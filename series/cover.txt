hw/arm: Add the Raspberry Pi 5 (raspi5b) machine

This series adds raspi5b, a model of the Raspberry Pi 5 Model B and its
Broadcom BCM2712 SoC: four Cortex-A76 cores, a GIC-400, UART10 (a PL011)
and UARTA (a 16550), the system timer, the watchdog and reset status
block, the RNG200, the Broadcom level 2 interrupt controllers, the SoC's
two GPIO blocks with their pin controllers, the HDMI ports' DDC I2C
controllers, the two SD hosts, and the VideoCore mailbox with the
firmware property channel, which answers for the Pi 5's clocks, power
domains and reboot flags as its firmware does. On the board,
system_powerdown presses the power button on a GPIO line, the activity
LED's changes are trace events, a monitor's EDID answers on HDMI0's DDC
bus, and -drive if=sd puts a card in the SD card slot, whose card-detect
switch drives a GPIO line. Every other block of the memory map is an
unimplemented-device placeholder. The RP1 south bridge, behind PCIe, is
not modelled yet, so there is no Ethernet, USB or 40-pin header.

Bare-metal code, the Pi's boot firmware and Linux run on it. The machine
boots like the Raspberry Pi firmware does: the guest enters at EL2 with
PSCI over SMC, or owns EL3 with secure=on. With secure=on, -bios loads
firmware such as TF-A's BL31 as the Pi's firmware loads its armstub, and
hands it the kernel and device tree the same way. Without -dtb the
machine generates a device tree, which validates against the kernel's
bindings. Either tree gets the changes the firmware makes before it
starts the OS, anew for each boot: the model and serial number, the
command line it builds, what /chosen reports about the boot and the
power supply, and seeds for KASLR and the RNG. The stock Raspberry Pi OS
kernel mounts its root file system from an SD card, on that tree or on
the firmware's bcm2712-rpi-5-b.dtb, started directly, by TF-A, or by
U-Boot, which loads it from the card.

The series is in four parts:

- The BCM283x device models get a Kconfig symbol each, so the BCM2712
  can select the ones it reuses without the Pi 1-4 boards. No
  functional change.

- Fixes to models the BCM2712 reuses, which apply to the older Pis too.
  The system timer now stops its comparators on reset and migrates them.
  The watchdog now counts down instead of resetting the machine as soon
  as it is armed, and the reset status survives the reset it reports.
  The property channel no longer answers a buffer the firmware could
  not read, answers a request cut short with the interface's error
  code, keeps every tag within the value buffer it declares, and
  answers the firmware and board identity tags Linux asks for and the
  notification it sends before a reset or a power-off.

- New models for the RNG200, for the Broadcom STB level 2 interrupt
  controller, GPIO controller, pin controller and I2C controller, for
  the BCM2712's SD host controller, and for the Pi 5's firmware property
  interface, a subclass of the BCM2835's; a 16550 change, an SDHCI
  change, two property interface changes, three target/arm changes TF-A
  needs, and four fixes for bugs found by the tests:
  - a property for the depth of the 16550's FIFOs, as UARTA's hold 32
    bytes and Linux fills them;
  - an SDHCI output that follows the card in the slot, for boards whose
    card-detect switch is a GPIO line, as on the Pi 5;
  - the property interface's tag switch moves into a function of its
    own, and a class method lets a subclass answer tags ahead of it, so
    that the Pi 5's firmware answers with its own values without
    changing the older boards' answers;
  - the Cortex-A76's IMPLEMENTATION DEFINED registers, without which
    TF-A stops in its reset handler;
  - a CPU property that sets MPIDR_EL1.MT, by which TF-A numbers the
    A76 cores;
  - a warm reset when software sets RMR_ELx.RR, as TF-A's CPU_OFF does
    to send a core back to its holding pen;
  - with the Security Extensions, a Non-secure write to GICD_SGIR could
    raise Group 0 SGIs;
  - a generic timer whose offset exceeds the count, such as the virtual
    timer with CNTVOFF_EL2 above CNTPCT, never fired;
  - the DDC's EDID device dropped out of a transfer in progress when the
    machine migrated, so the transfer's remaining bytes read as 0xff;
  - an SD card on a drive without a medium could not take one later, so
    no card could go into a board's empty slot.
  One more patch is a fix from master, which v11.1.1 lacks: SDMA now
  resumes after stopping at a buffer boundary, which U-Boot's reads
  need (725a8f107cc1). It leaves the series once rebased onto master.

- The SoC, the board, a qtest and the documentation.

Testing: the qtest covers every modelled device at register level, and
the -bios handoff. A bare-metal test suite runs on 1 to 4 cores, at EL2
and EL3, with and without a device tree, and on TF-A's PSCI. It covers
per-core timers and SGIs, SPI routing, PSCI, the mailbox, the firmware's
clocks and a tryboot, the watchdog and system resets, the RNG, the
level 2 interrupt controllers, GPIO interrupts, the UART and the SD
card's master boot record. Out of tree, TF-A, U-Boot and the EDK2 port
boot from an SD card, and Linux mounts its root file system from one.
The suite lives out of tree, with the rest of the development history:
https://github.com/hatter6822/rpi5_machine

The new files are added to the existing Raspberry Pi entry in
MAINTAINERS.
